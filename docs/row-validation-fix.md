# Register row validation correction

October 14, 2026. Fixes the confirmed ProjectB.md requirement gap: missing or ambiguous fields must be reported, and missing facts must remain visible.

Previously the capture parser silently skipped populated rows whose cell counts did not match the headers, or whose required business ID was empty. Now each such row retains its parsed cells, header context, exact table-row locator, reason and resolution need in source metadata. Exact original response bytes remain captured separately. A uniquely aligned disclosed owner is retained; otherwise the issue is assigned to the source-owner role without inferring field alignment or inventing a business ID.

Stage 02 records the issues as unresolved. Stage 04 turns them into evidence gaps; existing downstream processing carries those gaps into Stage 05, Stage 06 escalations and the final impact register and brief. Valid rows remain usable with partial record quality. When no valid rows remain, requested register content is unverified, diagnostic bytes/row issues remain available, and an explicit source gap accompanies the row gaps. Retrieval states retain the schema's existing vocabulary.

Parsing is restricted to the table containing the register headers. Empty grid slots, including Google Sheets' displayed row-number cell, and unrelated navigation tables are not treated as missing business records. A populated row with a missing ID still produces an issue.

Regression coverage includes SYSTEMS, EVIDENCE and CALENDAR; too few/many cells; whitespace-only IDs; valid rows mixed with invalid rows; no valid rows; empty grid/navigation exclusion; and end-to-end propagation into the snapshots, CSV and brief. The end-to-end check also verifies that known owners are preserved while misaligned owners are not guessed. Synthetic test inputs stay in temporary directories, never in the assessed source bundle.
